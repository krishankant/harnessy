Short-term: a small windowQuality drops before the window is full. Five fixes, cheapest first.

  1. 1Load just in timeKeep a path or a query, fetch the content with a tool
  2. 2Clear old tool resultsSwap them for one-line stubs. No model call
  3. 3CompactSummarize the oldest turns. One model call, some loss
  4. 4Keep notes on diskA todo list or progress file, re-read later
  5. 5Hand it to a subagentIt reads in its own window and returns a short answer

No context manager: 671 to 11,931 input tokens

With one: levels off near 3,600

Bounded, not cheaper. The managed run re-read files it had cleared and used more tokens in total.

Long-term: four decisionsThe store is the least interesting one.

Who writes, and when

The agent mid-task, or a background job after the run.

Mid-task is instant but easy to forget. Background adds no delay but lags.

What shape

One profile, many small facts, or a graph of dated relations.

One fact per record, as a full sentence.

How it gets back in

A small index that is always loaded, plus bodies fetched on demand.

A memory that is not in the window does not exist.

How it stays correct

Update in place. Put a date and a source on every memory. Check it on read. Expire and delete.

Most systems skip this one.

How shipped systems answer them

Claude Code keeps two stores: you write CLAUDE.md, Claude writes auto memory. Only the first 200 lines of its index load at the start.

Letta pairs each agent with a second one that rewrites memory while the first is idle.

Zep never deletes a contradicted fact. It marks the date it stopped being true.

What goes wrong in productionEach one, and the fix that helps most.

Stale memory

The agent confidently uses last quarter's fact.

Update in place, date it, verify on read

Memory poisoning

A web page tells the agent to save something. It replays in every later run.

No memory writes after untrusted input

Compaction loss

The summary drops the one detail that mattered.

Keep critical state in a notes file

Never recalled

The memory exists and the agent never looks.

A small always-loaded index

Cross-user leaks

One user sees what another said.

Scopes enforced in code, not in the prompt

Broken prompt cache

Recalled text changes the start of the prompt, and the bill goes up.

Load memory once, before the run

Build it in this order

Fix short-term firstClear old results, then compact
Facts in filesSemantic memory with a small index
One line per runEpisodic summaries
SearchKeywords, then embeddings, measured by evals
Scopes and a write gateBefore more than one user, or any untrusted input

Every step adds a store someone has to keep correct. Stop at the first one you don't need.
